### D1 — in-spec compact-viewport checks (360×800), as approved

Each of the three authorized smoke flows ends with a compact-viewport block asserting the responsive shell contract on the SAME authenticated session:

1. `setViewportSize({ width: 360, height: 800 })` (360 = the audit-proven width below the shell's `md`/768px flip; 800 = a compact-typical height).
2. Desktop sidebar absent: `getByRole("navigation", { name: "Primary navigation" })` → `toHaveCount(0)` (the sidebar is `hidden md:flex`; the closed drawer's identically-named landmark is unmounted — verified in `AppSidebar.tsx`/`MobileNav.tsx`).
3. The mobile `Open menu` trigger visible (`md:hidden` header).
4. Opening the drawer exposes the real `Courses` destination (`nav-config`'s shared source of truth).
5. Closing through the real `Close menu` control unmounts the drawer's landmark again.
6. The flow's core content pin still visible (login: `Welcome back!`; CRUD: `+ Create New Course`; profile: `Personal Information`).
7. The desktop viewport is restored defensively (the block is each flow's last step; restoration keeps the block position-independent).

Placement: login.spec step 6 (after the dashboard assertions), courses-crud step 7 (after the delete verification, still on /courses), profile-roundtrip step 6 (after the final persistence reload). **Coverage model (stated honestly):** this is NOT a full suite re-run at two viewports and MUST NOT be reported as one — each authorized flow exercises both viewport states within its single execution, using the already-authenticated session (no duplicated Keycloak logins), with one Chromium project and the worker/retry/timeout settings untouched.

### D2 — instructor CRUD + student negative affordance visibility, as approved

- **The CRUD loop now runs on the existing instructor test account** via `E2E_INSTRUCTOR_USERNAME` / `E2E_INSTRUCTOR_PASSWORD`, with its own explicit, actionable `test.skip` when the pair is absent and **no silent fallback** to the student credentials.
