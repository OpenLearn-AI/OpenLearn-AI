# ADR-0003: OCR benchmark — location, responsibility, and scientific sequencing

- **Status:** Accepted (2026-08-16)
- **Deciders:** Foundation cleanup task (Week 2); ratified by team review
  (Week 4, 2026-08-31)

## Context

Week 2 requires a reliable OCR ground-truth/evaluation pipeline. Three homes
were possible for it: (a) `backend/app/eval/` (roadmap W2 DoD #9's scaffold
location), (b) a separate repository (handbook Phase 2 mentions a standalone
repo), (c) `experiments/OCR/ocr-benchmark/` inside this monorepo. Prior state:
ad-hoc samples in `experiments/OCR/benchmarks/` (no provenance, no ground
truth, no metrics), an exploratory PaddleOCR notebook with absolute paths, and
no pinned experiment environment anywhere.

Repo boundary rule (DeveloperGuide §2): nothing under `experiments/` may be
imported by production code — experiments are reimplemented, not moved.

## Decision

1. The OCR benchmark lives at **`experiments/OCR/ocr-benchmark/`** as a
   self-contained, `uv`-pinned project with its own
   `pyproject.toml`/`uv.lock`, following the OCR Benchmarking Handbook
   Phase-2 layout (`core/` engine-agnostic, `adapters/` per-engine, `data/`
   split raw / ground_truth / processed, generated `results/` gitignored).
2. **Methodology authority** is the handbook; this ADR binds the repo
   structure to it. The roadmap's golden-set manifest schema
   (`tests/data/golden_pdfs/manifest.json` fields) is kept field-compatible so
   the benchmark can feed the roadmap's Week-10 evaluation without schema
   surgery.
3. **Scientific sequencing is mandatory** (handbook + foundation audit):
   ground truth → metrics → ONE engine → validate the harness end-to-end →
   only then add more engines. Benchmarking several engines before the
   harness is proven is prohibited.
4. **Ground truth is hand-verified only.** It is never generated by an engine
   under evaluation (PaddleOCR output must never become reference
   transcriptions). Annotation follows the guideline in
   `experiments/OCR/ocr-benchmark/docs/annotation-guidelines.md`.
5. **Provenance is mandatory**: every dataset document carries a rights status
   (`UNKNOWN` until evidenced) recorded in `docs/provenance.md`.
6. When the ingestion pipeline needs production OCR, the winning engine is
   **reimplemented** inside `backend/app/services/ocr/` to backend standards —
   the benchmark is never imported by product code.
7. `backend/app/eval/` (roadmap DoD) will be seeded later by wrapping the
   benchmark's proven `ocrbench.core` abstractions — not by building a
   second, competing evaluation framework first.

## Consequences

- One evaluation codebase; the backend eval harness inherits tested
  abstractions instead of duplicating them.
- Benchmark results are reproducible (pinned env, relative paths, gitignored
  generated outputs) and scientifically defensible (documented GT conventions,
  no circular ground truth).
- Engine screening (handbook Phase 3) decides which adapters get built —
  no adapter exists until its engine survives screening.

## Alternatives considered

- **Benchmark inside `backend/`** — rejected: OCR engines (PaddlePaddle,
  GPU torch variants) would pollute backend runtime deps and CI weight at a
  stage where the backend imports none of it; also violates the
  experiments-first evolution path.
- **Separate repository** — rejected for now: splits planning/CI/provenance
  governance; the monorepo location already isolates dependencies via uv. Can
  be extracted later if the dataset outgrows the repo.
