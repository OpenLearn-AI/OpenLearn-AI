# Database Migrations

OpenLearn-AI uses Alembic with SQLAlchemy's async engine to manage PostgreSQL
database schema migrations.

## Migration Structure

* `backend/alembic.ini` - Alembic configuration.
* `backend/alembic/env.py` - migration environment and database configuration.
* `backend/alembic/versions/` - database migration files.
* `backend/app/models/` - SQLAlchemy ORM models.

## Configuration

Create `backend/.env` from `backend/.env.example` and configure:

```env
DATABASE_URL=postgresql+asyncpg://<user>:<password>@<host>:<port>/<database>
```

Never commit `.env` or real database credentials.

## Common Commands

Run these commands from the `backend/` directory.

### Check the current migration

```powershell
python -m alembic current
```

### Show migration history

```powershell
python -m alembic history
```

### Apply all migrations

```powershell
python -m alembic upgrade head
```

### Roll back one migration

```powershell
python -m alembic downgrade -1
```

### Roll back to the base

```powershell
python -m alembic downgrade base
```

## Creating a Migration

After changing SQLAlchemy models, make sure the database is at the latest
migration first:

```powershell
python -m alembic upgrade head
```

Then generate a migration:

```powershell
python -m alembic revision --autogenerate -m "describe the change"
```

Review autogenerated migrations carefully before committing them.

## Migration Guidelines

* Do not modify an already-applied migration.
* Create a new migration for subsequent schema changes.
* Review autogenerated migrations before committing them.
* Test both upgrade and downgrade behavior when practical.
* Keep database credentials out of migration files and source control.
